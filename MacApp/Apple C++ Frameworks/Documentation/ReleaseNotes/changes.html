Change History

Changes for Release XV.I

Appearance

MacApp now uses the latest Window Manager functions for showing and selecting windows. These fixes were primarily made so that floating windows were handled properly.

TTabbedView now supports tab panels within tab panels.

Updated TextBox_AC so it draws the background correctly regardless of the vertical placement of the text.

Carbon Events

Added support for mouse-up events and click counting.

Handle a kHICommandQuit command as if it were cQuit.

Fixed a problem that caused scroller scroll bars to not update correctly under Mac OS X and Carbon Events.

Clipboard

A general solution has been implemented for writing the clip view to the desk scrap in Carbon. Previously, each view needed special case code in its cut and copy commands, but only TTEView had the needed code, so other views such as TWEView did not get their data into the desk scrap. Now TCommand::ClaimClipboard will make sure the clip view is exported when running on Carbon. Developers should be aware that if they have any custom views with cut or copy commands that don't go through TCommand::ClaimClipboard, they will need to either add some code, or change their implementation to go through the standard mechanism.

Printing

Previously, if no printer had been chosen and a print command was executed an alert was presented explaining:

The Print command could not be complete because the selected printing resource could not be found. Use 'Chooser' to select a printer and try again.

This occurred because MacApp was throwing a custom error code (-20005). MacApp printing code has now been changed to throw a 'kPMNoDefaultResource' (-30872) and the message reported in the alert is:

The Print command could not be complete because no printer has been selected. Use 'Chooser' to select a printer and try again.

Your code will need to be modified if you catch the old error code of -20005.

FTLString_AC

FTLString_AC is now its own class instead of derived from a template. The implementation of the old FTLBasicString_AC worked only for <char> and would not have worked for <wchar_t>, so it was better to simplify it.

FTLString_AC has more constructors and operators to make it easy to create a FTLString_AC from a standard string or a CF string, and vice-versa. The FTLString_AC iostream functions are now implemented, and some bugs have been fixed.

FTLString_AC now compiles with GCC and the g++ standard library. The EHTest sample program has been updated to build and run with GCC.

MultiLocale

The 'LMap' and 'IRMI' resources have been replaced with the 'LOCL' resource. The locale name is obtained from the LOCL resource name. The locale list within the CMultiLocale_AC class is now publicly accesible.

Removed an invalid assertion at top of GetReverseMappedResInfo.

Streams

NewByClassID, NewByClassName and NewBySignature so they no longer throw an exception. If they encounter an error in creating an object, they will return NULL.

Fixed RegisterSignature to replace old signatures in case it is called more than once for the same signature.

Fixed WriteStdObject to write the class name if there is no signature. Only register class if we get a classDesc in ReadObject. Also return a false in ReadObject on a NULL object.

Removed CStream_AC:: ReadString that was used only for qBackwardCompatible.

Threads

qWantsMP is now turned on for Carbon builds of MacApp. CMPThread_AC works on Mac OS X as well as 9.1.

The definition of CPreemptiveThread_AC has been fixed so it is a CMPThread_AC if building for PowerPC and qWantsMP is true, and it is a CThreadMgrThread_AC if building for 68K. This means that if you are building for PowerPC and you don't enable MP, you can use only cooperative threads.

FracApp MP has been fully Carbonized and now works on Carbon and Mac OS X. FracApp now draws correctly on displays with more than 256 colors. This required removing support for palette animation. Obsolete code for offscreen drawing without 32-bit QuickDraw and for running without the thread manager has also been removed.

CodeWarrior Pro 7 Support

Projects have been added for building with CodeWarrior Pro 7. Because CodeWarrior Pro 7 does not support 68K, you must use the included CodeWarrior Pro 6 projects to build for 68K.

Project Builder Support

MacApp can now be built in Project Builder using precompiled headers. If you want to use precompiled headers to build the MacApp static libraries, add MacAppHeaders_d.h (or MacAppHeaders_n.h) to the implicitly included headers, before MacAppPrefix.h, and check the precompile box.

Examples

Brought back the script menu in DemoText.

Added a tabs panel inside a tabs panel to the Appearance sample.

Added a floating window language controller to the Multilocal sample. Added Italian and Danish resources.

Fixed some bugs in the clipboard support in IconEdit.

Miscellaneous

Improved performance on Mac OS X by minimizing calls to HiliteMenu(0).

Fixed a typo: the CDrawingEnvironmentManager was missing the '~' character.

Fixed a crashing bug in NavDisposeReply on Mac OS X by making sure we always initialize validRecord to false in the NavReplyRecord.

Fixed TApplication:: CanOpenDocument to correctly interpret the value returned from a Nav Services object filter as meaning a file can be displayed (opposite of the return value for standard file).

Corrected the validate test in TDialogBehavior:: Dismiss.

Changed TEditionDocument to not throw if the edition settings resource is missing. If a document is created on an operating system that doesn't have the Edition Manager, it won't have the edition settings resource, but that should not prevent it from being opened in a Classic application that does have Edition Manager support.

Added a ResizableWindow method to TWindow to help better determine whether to draw a resize icon.

Fixed TWindow to defer registration of its drag handler until fWMgrWindow exists. This prevents a duplicate handler error from the drag manager, because each window is now registering its handler for a unique WindowRef instead of NULL.

Added definitions for ClusterBehavior and FlatBackgroundBehavior to ViewTypes.r.

Fixed TTabbedView so it passes its fDocument to the tab panes it creates. This ensures that the views inside the tab panes will be created with the same document instead of NULL.

TSetPropertyCommand was fixed so it doesn't assign NULL to a CAEDesc_AC, because the NULL value is interpreted as an AEDesc* and dereferencing it can cause a crash.

Added some accessor methods for use by view editors.

Fixed CFSSpec_AC:: GetPathName to place the delimeter on the correct side of the newly added directory.  

The Carbon version of DisableMenu_AC now calls DisableMenuItems_AC(0) to disable the entire menu and not just the items in it.

Changes for Release XV final (since Release XV beta) 

Drag and Drop

On Mac OS X the Drag Manager may call the application back with a different drag reference than the one the application started the drag with. The internal implementation in UDragDrop now has some additional drag reference parameters so it can deal with this correctly.

Project Builder

The size of a bool and the bit pattern that indicates true in a bool are different in GCC than they are in CodeWarrior or MrCpp. CStream_AC now uses an intermediate Boolean variable for reading and writing bool values. Developers that use CDataFilter_AC should be aware that bool values now go through FilterOutputBoolean and FilterInputBoolean. These methods have special names so they won't be confused with FilterOutput(char&) and FilterInput(char&).

Different compilers may encode the class name for run time type identification in different ways. CodeWarrior stores an unmangled name that is human readable. GCC stores a fully mangled name. Visual C++ stores a name with the word "class " before it. The ClassRegistration_AC unit was assuming that the RTTI name for the class was the same as the class name. This has now been fixed. As part of the fix, the internal implementation of the REGISTER_CLASS_AC and REGISTER_SIGNATURE_AC macros has changed, so it is no longer possible to register a class without including the class definition.

Several minor changes were made to the code to fix conditions that were getting warnings from GCC. There still are several "choosing non-const" warnings when compiling ACS or MacApp. Those are caused by a bug in the compiler and should be ignored. Some of the warnings will incorrectly be reported as errors.

View Drawing Changes

The basic view drawing code has been changed to provide better support for drawing environments and exception handling.

CDrawingEnvironmentManager is a new stack-based class that ensures that CompleteDrawing will be called even if the view's Draw code throws an exception.

NotifyDrawFailed now returns a bool that controls whether to continue drawing other views or to rethrow the exception. The area parameter has been removed from NotifyDrawFailed and the exception parameter has been removed from DrawFailed. This gives a better division of responsibility between the methods. The code is still doing the same thing, so the API changes will only affect applications that are overriding one or more of the changed methods.

Clipboard

The clipboard code has been significantly improved, and now hides all of the differences between the Carbon and classic scrap managers. Some minor changes may be required to application code to use the new APIs. The main thing is to go through the accessors and to have consistent error handling.

CClipboard_AC has been redesigned so it's a pure wrapper for the Carbon and classic scrap managers. For convenience, several varieties of Get and Put methods are provided so you can choose Carbon-style or classic-style APIs. All of them should work on both Carbon and classic. There even is a GetFlavorInfoList method that returns a vector of flavor information.

CClipboard_AC includes debug support for tracing the scrap state. To use it, set a breakpoint in the TraceScrapState function and set pTraceStackState to true.

All of the fields of TClipboardMgr and TDeskScrapView have been made protected. New accessors have been added as necessary, and the other objects in the MacApp framework have been changed to go through the accessors.

The error handling policy for the scrap Get and Put methods wasn't consistent. Now they all have void return types and will throw an exception if there is an error. The exception is GetFlavorSize which returns a long that may be a size or an error (like the Classic GetScrap). It will never throw. Use GetFlavorSize to check if a flavor exists in the scrap.

CString_AC

CAEString_AC::GetMaximumSize has been fixed to return a positive number. Please note that the actual maximum size of a string depends on available memory and is not easy to estimate. GetMaximumSize returns the theoretical maximum size of a string, which is 2 GB on PowerPC.

Brought back the old CAEString_AC class and renamed it to CAEStr255_AC. Applications that really want just a pascal string and don't mind the 255 character limit may use CAEStr255_AC.

Added a new switch qTrainingWheels that is similar to qBackwardCompatible except that qTrainingWheels defaults to true and qBackwardCompatible defaults to false. Added some training wheel functions for easier conversion from CPascalString_AC to CString_AC. Made the 'explicit' keyword for the CString_AC constructors conditional on !qTrainingWheels. This allows a CString_AC object to be automatically created from a pascal string.

Added debug support for tracing conversion and copying of strings. To see how strings are being used in your application, run under a debugger and set CStringTrace_AC::fgTrace to true.

kEmptyString_AC, also known as gEmptyString, has been changed from a global object to a macro for the constant empty string "\p". This was done because copying a string object is not as efficient as defining a constant local to a function.

Carbon Events

Use TrackMouseLocationWithOptions for tracking. Now MacApp supports auto-scrolling while using Carbon Events.

Fixed a problem where MacApp's Carbon Event handler was trying to handle keyboard events for non-MacApp windows. This was keeping keyboard events from getting to Nav Services windows.

Fixed TDocument to call InvalidateMenus when the document's change count is modified. This got the Save menu item to be enabled correctly. In general, if a DoSetupMenus method enables a menu item conditionally based on some data, then the object should call InvalidateMenus whenever that data is changed.

TOSADispatcher now calls DidCarbonEvent after handling an Apple Event.

Do initialization for Carbon Events in CreateToolboxWindow instead of DoPostCreate. That way it's more likely to get done. Also need to initialize for Carbon Events in the TWindow constructor if it was given a window manager window, because in that case CreateToolboxWindow isn't going to be called.

Changed TDialogBehavior to use RunAppModalLoopForWindow instead of PollEvent if the application is using Carbon Events.

qCarbonEvents now requires Mac OS X 10.0.3, or the CarbonLib 1.3.1 SDK, or later. Earlier versions of the CarbonLib SDK don't have all the APIs MacApp needs. Similarly, HasCarbonEvents_AC now will return true only if the Carbon version is 1.3 or greater.

Printing

Reenable use of PMGetAdjustedPaperRect in GetPaperRect. Can also now call PMGetScale in GetScale.

Fixed an erroneous debug warning in TClassicPrintJob.

Controls

Install font settings in TCtlMgr::CreateControl in case the control is not in a window at DoPostCreate time.

Fixed TEditText to set the correct text style before imaging.

There is a problem with the proper font being shown for popup control titles. This is a long-known problem in the Control Manager (not in MacApp) and it is not going to be fixed since the solution is too complex. The Toolbox team has suggested using a separate static text field for the popup title instead.

The MacApp examples have been changed to use static text for popup labels. TPopup::SetTitle will report a debug warning if it is called with a non-empty string.

Examples

Several problems have been fixed in DemoWDEF. There is one remaining known problem: the custom windows in the Carbon build are behaving as if they were modal.

The Scriptable Movie Viewer now works with QuickTime 5. There was a problem because the 'play' user data atom changed in size. Moviewer now gracefully ignores data that it didn't expect.

Miscellaneous

Added redraw parameter to UpdateScrollAmounts. Hide and shown the pen if this parameter is false.

Changed TDocument::GetObjectProperty so documentless windows are only reported on gDebugMsg and gIntenseDebugging.

Changed the default of qNeedsSystem8_5 to false so MacApp Carbon applications may run on Mac OS 8.1 with Carbon Lib 1.0.4.

Fixed bugs in TApplication::CanOpenDocument and GetNavFileTypes that could cause a crash in Nav Services object filter functions.

Added a GetData method to CAEDesc_AC. Changed SizeOfNthItem and SizeOfKeyDesc to not throw.

Work around process not brought to front by click on Mac OS X.

Limitations & Issues

Features Not Implemented

  • Printing - Quartz printing not implemented.
  • Networking - The Networking framework builds with Carbon and the Carbon version runs on Mac OS 9, but it hasn't yet been made to run on Mac OS X.
  • Java - Incomplete.

Features Not to be Supported

  • Carbon SDKs prior to v1.2.
  • Universal Interfaces prior to v3.4.
  • AppleGuide is not supported in Carbon.
  • The ATA Manager is not supported under Carbon. Access to hardware information can be accomplished by including separate modules that call the Name Registry when running under Mac OS 9 and the IOKit when running under Mac OS X.

Known Issues

In addition to the Limitations listed above you should be aware of these issues:

  • Carbon applications require a larger partition when running under Mac OS 9 than do the equivalent Mac OS 9 applications. We recommend that you up the partition sizes by approximately 1 MB.
  • If you find that your window titles are not being set properly then first check to be sure that the template window title is either empty or contains the substring '<<<...>>>', allowing for substitutions.
