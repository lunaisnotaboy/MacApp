Features

Here is some detailed information about substantial changes which have been made to MacApp Release XV:

Project Builder

MacApp Release XV includes extensive support for building with Project Builder. For detailed information, see the page on Building MacApp with Project Builder.

Mac Toolbox

Some of the implementation in MacApp's TWindow class is now taken care of by the ACS CWindow_AC class. The TWindow API is still the same.

MacApp now includes preliminary support for Carbon Events. The flag qCarbonEvents is true at compile time if Universal Headers version supports Carbon Events. This should be an issue only if compiling with old headers, because the current publicly available headers support Carbon Events. A flag, fUseCarbonEvents, has been added to TDispatcher to control whether the application uses Carbon Events at run time. If fUseCarbonEvents is true, the application will use Carbon Events if they are available, otherwise TDispatcher clears the flag and falls back to a standard main event loop. Since this is the first release with Carbon Event support, the flag is defaulted to false. Developers who are interested in getting the best possible performance on Mac OS X should consider setting fUseCarbonEvents. Please let the Apple C++ Frameworks team know how the Carbon Event support works in your application.

MacApp's Carbon Event support requires Mac OS X, or Mac OS 8.6 or later with CarbonLib 1.3.1 or later.

MacApp Carbon applications require Mac OS X, or Mac OS 8.1 or later with CarbonLib 1.0.4, and on Mac OS 8.6 or later with CarbonLib 1.3.1 or later.

C++ Standards

MacApp Release 15 increases the use of C++ Standard Library components such as std::string and certain container classes.

CString_AC

The use of std::string is implemented via a new class, CString_AC, found in the ACS framework. CString_AC is a thin wrapper on std::string with some additional functionality to allow creation from resources, pascal strings, etc. Please refer to the ACS release notes for complete details on this new string class.

In prior releases, MacApp has used CStr255_AC, CStr63_AC, etc. (all of which are forms of CPascalString_AC) pervasively. Many of these usages have been replaced with CString_AC, though the transition has not been fully completed in this release. Generally, anything relating to document and window titles have been changed to CString_AC. Also, certain utility functions (such as MAReplaceText) now utilize this new string class.

In many cases, you can simply replace the use of a CStr255_AC with a CString_AC since CString_AC provides many of the same constructors and operators. For example, there is a constructor that takes a ResNumber and index and which will instantiate a CString_AC from a STR# resource.

There are some places in MacApp where you will need to retrieve a Str255 from a CString_AC in order to pass a string to a Toolbox call. CString_AC provides an 'AsStr255' function for this purpose or you may use the CStr255_AC(std::string&) constructor.

Apple Class Suites

The MacApp Project Builder and CodeWarrior projects now include the ACS sources instead of the ACS static library. There are also targets in the MacApp Project Builder projects that allow the MacApp static library to be built to use the ACS.framework.

Miscellaneous

DoNeedDiskSpace has been made const. The const-ripple-down effect is a result and some of your code will likely require modifications.
