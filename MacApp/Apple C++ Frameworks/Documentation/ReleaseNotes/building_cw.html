Building with CodeWarrior

MacApp

Requirements

MacApp builds with CodeWarrior Pro 6 and CodeWarrior Pro 7, on Mac OS X and Mac OS 8 and 9.

CodeWarrior Pro 6 Support

MacApp supports building with CodeWarrior Pro 6. The recommended configuration is CodeWarrior Pro 6.2.

CodeWarrior Pro 6 comes with a modified version of the CarbonLib 1.0.4 SDK. For Carbon development, we strongly recommend installing the CarbonLib 1.4 GM SDK, which is freely downloadable from the Apple Developer web site. The CarbonLib SDK contains the latest versions of the headers, so it is preferred for non-Carbon development too.

CodeWarrior Pro 7 Support

All of the necessary projects are in the 'CWP7 Support' folder. The layout of the 'CWP7 Support' folder is the same as 'CWP6 Support', except that CodeWarrior Pro 7 does not support development for 68K. Use CodeWarrior Pro 6 for building 68K applications.

CodeWarrior Pro 7 has greatly improved support for Mach-O development, but the MacApp projects are not quite ready yet, so they are not included. Use Project Builder for Mach-O development.

Installing the Components

The Carbon Porting Guide in the CarbonLib SDK recommends installing the 'Carbon Support' folder next to the CodeWarrior 'MacOS Support' folder. The Apple C++ Frameworks team recommends copying the contents of the 'Carbon Support' folders to the corresponding folders inside 'MacOS Support', so you have a single, simple configuration with the latest of everything. For example, copy the contents of the ':Carbon Support:Universal Interfaces:CIncludes' folder to the ':MacOS Support:Universal Interfaces:CIncludes' folder. Do not copy at the folder level because there are CodeWarrior specific files that you want to keep.

Building the Libraries

All of the necessary projects are in the appropriate CW support folder. The layout of each CW support folder matches the layout of the Apple C++ Frameworks sources.

The MacApp library build process has been simplified by including the ACS sources in the MacApp library projects. This also ensures that the ACS and MacApp sources are compiled consistently. It still is necessary to build the MacApp library and the MacApp resources. The easiest way to do that is to build one or both of the top-level projects.

For 68K and PPC development:

  • MacAppACSRes.prj

For Carbon development:

  • MacAppACSRes_car.prj

Building the Examples

The example projects are in the 'Examples' folder inside the 'MacApp' folder.

There are aggregate projects that will build all the MacApp examples, or you can individually build just the ones you want.

All of the example projects will automatically rebuild the MacApp libraries if necessary, but in order to reduce build times they don't automaticallly rebuild the MacApp resources.

There are also examples in the 'Network' folder and the 'ACS' folder.

Building Your Own Application

Drag the MacApp library project you want to use into your application project, and drag in the built MacApp libraries and resources. Make sure the target settings in your application project match the corresponding settings in the library project, especially the C/C++ language, processor, and optimization settings.

For Classic PPC debug applications, drag in TidyHeapSharedLib from inside the TidyHeap/SharedLib folder. TidyHeap will work without the shared library, so it can and probably should be weak linked.

The easiest way to get the libraries you need is to open one of the example projects and drag files from the example project to your application project.

If you are upgrading your application from R13 or R14, you will want to remove the ACSLib project and ACS libraries from your application project. Otherwise you will get a very large number of duplicate definition warnings.
