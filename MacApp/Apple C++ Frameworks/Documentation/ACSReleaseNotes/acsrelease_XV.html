ACS Release XV.I

The main features of ACS Release XV are:

  • Project Builder support.
  • Support for Core Foundation and Carbon Events.
  • Further modernization and support for C++ standards.
  • ACS now can be installed and used by itself, without MacApp.

Release XV.I is a maintenance release of XV. It includes bug fixes and support for CodeWarrior Pro 7.

Features

Project Builder

ACS supports building Mach-O executables in Project Builder, on Mac OS X. ACS can be built as either a static library or as ACS.framework. There are debug and non-debug versions of each. There are also Project Builder projects for building the ACS examples.

An 'ACS Tool' project template is provided that makes it very easy to create new Project Builder projects using ACS.framework.

The next page has detailed instructions on Building ACS in Project Builder.

Mac Toolbox

ACS includes a new suite called 'Foundation' that provides C++ wrappers for working with the CoreFoundation.

ACS includes a new suite called 'FTL' that provides access to Core Foundation containers through interfaces that are compatible with the C++ standard library. For example, FTLString_AC allows a Core Foundation string to be accessed just like a standard string.

A new ACS class, CWindow_AC, for working with toolbox windows.

ACS now provides a set of classes for safely and conveniently accessing the contents of Carbon Events.

C++ Standards

Support for using standard strings in conjunction with pascal strings. Utilization of standard strings in the framework.

CString_AC has been added. Many uses of CStr255_AC have been changed though this effort has not been completed. CString_AC is a light-weight wrapper on std::string that adds some compatibility with Pascal strings and CStr255_AC. Generally speaking, you should be able to use CString_AC in places where you currently use CStr255_AC.

There has been some effort to move to the Standard C++ Library containers thoughout ACS though this has not yet been completed. For example, see ClassRegistration_AC.h/.cpp.

Apple Class Suites

ACS stands on its own and can be downloaded without also pulling in all of MacApp. It includes Project Builder and CodeWarrior support folders and a set of examples.

The folder organization of ACS has been simplified and cleaned up. The 'includes' and 'sources' folders have been merged in order to reduce the number of folders and make it easier for development environments to find the files. The "suite headers" such as Appearance_AC.h and Imaging_AC.h were not defining anything that was actually being used, so they have been removed. The Appearance, Containers, Help, Java, and Memory suites are used only with MacApp so they are not included in the standalone version of ACS. A couple of files have been moved from one suite to another when it seemed to make sense. For example, CString_AC, CPascalString_AC and StdStringUtils_AC are now in the Text suite.

ACS works well with Metrowerks PowerPlant. An example has been added that demonstrates this (ACS PP Counter). Currently, you must build ACS for use with PowerPlant. The biggest change is that CMacException_AC is based on PowerPlant::LException when __PowerPlant__ is defined. In this way, PowerPlant code can call ACS code and any CException_AC that is thrown will be caught as an LException. It does not work the other way around, but this should not cause any problems since ACS does not call into PowerPlant and thus will not need to catch exceptions thrown from within PowerPlant.
