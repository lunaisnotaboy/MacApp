ACS Release XV.I Change History

Changes for Release XV.I

Appearance

Updated TextBox_AC so it draws the background correctly regardless of the vertical placement of the text.

FTLString_AC

FTLString_AC is now its own class instead of derived from a template. The implementation of the old FTLBasicString_AC worked only for <char> and would not have worked for <wchar_t>, so it was better to simplify it.

FTLString_AC has more constructors and operators to make it easy to create a FTLString_AC from a standard string or a CF string, and vice-versa. The FTLString_AC iostream functions are now implemented, and some bugs have been fixed.

FTLString_AC now compiles with GCC and the g++ standard library. The EHTest sample program has been updated to build and run with GCC.

MultiLocale

The 'LMap' and 'IRMI' resources have been replaced with the 'LOCL' resource. The locale name is obtained from the LOCL resource name. The locale list within the CMultiLocale_AC class is now publicly accesible.

Removed an invalid assertion at top of GetReverseMappedResInfo.

Streams

NewByClassID, NewByClassName and NewBySignature so they no longer throw an exception. If they encounter an error in creating an object, they will return NULL.

Fixed RegisterSignature to replace old signatures in case it is called more than once for the same signature.

Fixed WriteStdObject to write the class name if there is no signature. Only register class if we get a classDesc in ReadObject. Also return a false in ReadObject on a NULL object.

Removed CStream_AC:: ReadString that was used only for qBackwardCompatible.

Threads

The definition of CPreemptiveThread_AC has been fixed so it is a CMPThread_AC if building for PowerPC and qWantsMP is true, and it is a CThreadMgrThread_AC if building for 68K. This means that if you are building for PowerPC and you don't enable MP, you can use only cooperative threads.

Miscellaneous

Fixed CFSSpec_AC:: GetPathName to place the delimeter on the correct side of the newly added directory.  

The Carbon version of DisableMenu_AC now calls DisableMenuItems_AC(0) to disable the entire menu and not just the items in it.

CodeWarrior Pro 7 Support

Projects have been added for building with CodeWarrior Pro 7. Because CodeWarrior Pro 7 does not support 68K, you must use the included CodeWarrior Pro 6 projects to build for 68K.

Changes for Release XV final (since Release XV beta)

Project Builder

The size of a bool and the bit pattern that indicates true in a bool are different in GCC than they are in CodeWarrior or MrCpp. CStream_AC now uses an intermediate Boolean variable for reading and writing bool values. Developers that use CDataFilter_AC should be aware that bool values now go through FilterOutputBoolean and FilterInputBoolean. These methods have special names so they won't be confused with FilterOutput(char&) and FilterInput(char&).

Different compilers may encode the class name for run time type identification in different ways. CodeWarrior stores an unmangled name that is human readable. GCC stores a fully mangled name. Visual C++ stores a name with the word "class " before it. The ClassRegistration_AC unit was assuming that the RTTI name for the class was the same as the class name. This has now been fixed. As part of the fix, the internal implementation of the REGISTER_CLASS_AC and REGISTER_SIGNATURE_AC macros has changed, so it is no longer possible to register a class without including the class definition.

Several minor changes were made to the code to fix conditions that were getting warnings from GCC. There still are several "choosing non-const" warnings when compiling ACS or MacApp. Those are caused by a bug in the compiler and should be ignored. Some of the warnings will incorrectly be reported as errors.

Clipboard

CClipboard_AC has been redesigned so it's a pure wrapper for the Carbon and classic scrap managers. For convenience, several varieties of Get and Put methods are provided so you can choose Carbon-style or classic-style APIs. All of them should work on both Carbon and classic. There even is a GetFlavorInfoList method that returns a vector of flavor information.

CClipboard_AC includes debug support for tracing the scrap state. To use it, set a breakpoint in the TraceScrapState function and set pTraceStackState to true.

CString_AC

CAEString_AC::GetMaximumSize has been fixed to return a positive number. Please note that the actual maximum size of a string depends on available memory and is not easy to estimate. GetMaximumSize returns the theoretical maximum size of a string, which is 2 GB on PowerPC.

Brought back the old CAEString_AC class and renamed it to CAEStr255_AC. Applications that really want just a pascal string and don't mind the 255 character limit may use CAEStr255_AC.

Added a new switch qTrainingWheels that is similar to qBackwardCompatible except that qTrainingWheels defaults to true and qBackwardCompatible defaults to false. Added some training wheel functions for easier conversion from CPascalString_AC to CString_AC. Made the 'explicit' keyword for the CString_AC constructors conditional on !qTrainingWheels. This allows a CString_AC object to be automatically created from a pascal string.

Added debug support for tracing conversion and copying of strings. To see how strings are being used in your application, run under a debugger and set CStringTrace_AC::fgTrace to true.

kEmptyString_AC, also known as gEmptyString, has been changed from a global object to a macro for the constant empty string "\p". This was done because copying a string object is not as efficient as defining a constant local to a function.

Miscellaneous

Added a GetData method to CAEDesc_AC. Changed SizeOfNthItem and SizeOfKeyDesc to not throw.
