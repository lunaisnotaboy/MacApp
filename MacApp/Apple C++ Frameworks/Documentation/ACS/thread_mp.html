Preemptive Threads

Preemptive thread support takes advantage of MP available in hardware. It includes the classes CMPThread_AC, CPreemptiveThread_AC, CMPFailure_AC, CMPMutex_AC, CMPQueue_AC, and CMPSemaphore_AC

CMPThread_AC

CMPThread_AC is a subclass of CThread_AC that knows how to run itself as an MP task.

To use CMPThread_AC, create your own subclass and override the Run method. Make a new instance of your subclass and assign it to a CThreadRunner_AC to start it.

If you want MP tasks on PowerPC and don't care about 68K preemptive thread support, you could subclass from CMPThread_AC instead of CPreemptiveThread_AC. However, it still is better to subclass from CPreemptiveThread_AC because that class is about providing a particular kind of functionality, while CMPThread_AC is a class that wraps a particular kind of implementation.

As a convenience, CMPThread_AC defines CMutex, CQueue, CSemaphore, CTempMutex, CTempQueue and CTempSemaphore as types based on the MP implementations: CMPMutex_AC, etc. If you use these types in your code, they will map onto the appropriate synchronization classes for the thread class that you are inheriting from.

CMPThread_AC provides FailIf and ProgramBreak functions that map onto MPFailIfOSStatus_AC and MPProgramBreak_AC.

CPreemptiveThread_AC

On PowerPC, CPreemptiveThread_AC is a CMPThread_AC. On 68K, it's a CThreadMgrThread_AC that it starts as a kPreemptiveThread.

CMPFailure_AC

CMPFailure_AC provides a way for code in an MP task to signal failure.

It does not appear that C++ exceptions work in MP tasks. Instead of calling ThrowIfOSErr_AC, call MPFailIfOSStatus_AC. If the provided status is an error, it will terminate the current task with that error status. Please note that catch blocks and destructors will not be called when the task is terminated. Since C++ exceptions don't work in tasks, the catch blocks and destructors don't get called if you throw either. Destructors still work for cleanup when there aren't any errors, but otherwise you can't rely on C++ exception handling in MP tasks. The best approach is to make sure the code in an MP task will never fail at runtime.

MP tasks now have a task exception mechanism but it is more for task debugging. It does not correspond to the C++ language exception mechanism that can operate at the object and function level. MPFailIfOSStatus_AC may be changed to throw an MP task exception in addition to terminating the task. That will provide more information about the failing task, but it's not possible to catch an MP task exception in the same task that threw it.

If it becomes possible to use C++ exceptions in MP tasks, MPFailIfOSStatus_AC will be changed to throw a C++ exception.

MPFailIfOSStatus_AC can be called from non-preemptive code. If it is safe to throw a C++ exception, it calls ThrowError_AC or DebugThrowError_AC. If it is in an MP task, it calls MPProgramBreak_AC to report the failure, then terminates the task.

CMPFailure_AC provides MPProgramBreak_AC functions for safe debugging from MP tasks. The function is overloaded so you can give either a pascal string or printf style arguments.

CMPMutex_AC

CMPMutex_AC is a simple wrapper on a MPCriticalRegionID.

CTempMPMutex_AC is a CMPMutex_AC that automatically deletes the mutex in its destructor.

CMPQueue_AC

CMPQueue_AC is a simple wrapper on a MPQueueID.

CTempMPQueue_AC is a CMPQueue_AC that automatically deletes the queue in its destructor.

CMPSemaphore_AC

CMPSemaphore_AC is a simple wrapper on a MPSemaphoreID.

CTempMPSemaphore_AC is a CMPSemaphore_AC that automatically deletes the semaphore in its destructor.
