Foundation Template Library

The Foundation Template Library classes are the high-level APIs in ACS. At this moment, the only high-level class implemented is FTLString.

FTLString

FTLString is designed to have the same interface as the C++ Standard Library string class, and its implementation is based on CFString. The purpose of FTLString is to make it easier for developers to work with CF strings, by providing an API they already know, and by enabling them to use Standard Library algorithms on CF strings. Because of differences between the Standard Library and Core Foundation, FTLString cannot perfectly emulate Standard Library strings, and it cannot provide full access to the lower level CF string APIs. It is intended only to make it easier to use CF strings and Standard Library strings in the same program.

FTLString is implemented as a string of <char>, corresponding to the Standard Library string class, which is a std::basic_string<char>. There should also be an FTLWideString class. CFString is defined to fundamentally be a Unicode string, so it actually would work better with FTLWideString than FTLString. The reason why FTLString was implemented first is that <char> strings are more widely used.

Appending NULL characters to a string does not work with CF strings. FTLString checks and doesn't call CF to append the character if it is NULL. If you have an algorithm that depends on inserting NULL characters in strings, try using a Standard Library string as an intermediate instead of using the algorithm directly on an FTLString.

The FTLString functions tested by the EHTest example application appear to work. There is one test that fails the first time, then appears to work on the second iteration.

The stream operators >> and <<, and the getline functions are not implemented yet.
