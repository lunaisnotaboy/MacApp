Using ACS

Using ACS by Itself

Using ACS by itself is appropriate for command line or console tools, and for applications that already have a graphical user interface. If you are starting a GUI application from scratch, you really should use a GUI framework such as Cocoa, MacApp or PowerPlant.

Starting to use ACS in a tool or existing GUI application is easy. Simply include an ACS library project into your application project, add paths to the ACS Suites folder, and start using ACS classes.

Using ACS with PowerPlant

ACS has many utility classes that can be helpful when used with PowerPlant. For example, the imaging classes CPoint_AC, CRect_AC, CFixedPoint_AC, CFixedRect_AC and CMatrix_AC are unique to ACS. Since they do not have any counterparts in PowerPlant, they can be used without creating any conflicts. Other classes, such as TemplateTempHandle in ACS, have counterparts in PowerPlant, but the ACS version is more efficient, safer, and easier to use. In some cases the PowerPlant APIs will require using a specific PowerPlant class, but most of the time it works just as well to use an ACS class. Both PowerPlant and ACS are designed to be compatible with the Macintosh toolbox, which tends to make them compatible with each other.

The ACS exception class, CException_AC, is conditionally compiled so it derives from PowerPlant's LException when ACS is built with PowerPlant. This ensures that exceptions thrown from ACS utility classes are fully compatible with PowerPlant's exception handling.

The ACS suites that are likely to be of interest to PowerPlant developers are:

  • The Core suite, especially CAutoPtr_AC, CHandle_AC and CRefCountingPtr_AC.
  • CFSSpec_AC in the Files suite.
  • The Foundation suite.
  • The Imaging suite.
  • The QuickTime suite.
  • The Threads suite.
  • The Toolbox suite, especially the Apple Event classes, CCarbonEvent_AC, and TemplateUPP_AC.

The Counter example demonstrates including ACS in a PowerPlant application. The basic strategy is to include both the ACS and PowerPlant sources in the project, and to use a prefix file that includes both the ACS and PowerPlant switches before any other headers.

Using ACS classes in conjunction with PowerPlant has a minimal impact on the application footprint. The version of the Counter example using ACS is only 4K bytes larger than the version using only PowerPlant. In other words, the impact of using ACS is the same as if you had written the equivalent classes using PowerPlant, except the ACS classes are already written for you.

Using ACS with MacApp

The MacApp libraries already include ACS, so no extra work is required to use ACS in a MacApp application. You can also use the same copy of ACS to build ACS-only or ACS-PowerPlant applications. Simply use an ACS library project instead of a MacApp project, or include the ACS sources in your application project.
