Toolbox

This suite contains a set of classes which generally represent key portions of the Macintosh toolbox such as the clipboard. This suite is currently undergoing major revision.

CAEDesc_AC, etc.

CAEDesc_AC

The AEDesc wrapper, CAEDesc, has been moved from MacApp into ACS and is now called CAEDesc_AC.

It is now possible to construct a CAEDesc_AC directly from a pointer if you know the descriptor type using the constructor:

CAEDesc_AC(DescType theType, const void* dataPtr, Size dataSize); // Construct from data of a known type.

A CAEDesc_AC can also be constructed from an instance of CAEValue_AC, another a new class that is described below.

CAEDesc_AC(const CAEValue_AC& value); // Construct from an AEValue.

release, reset and IsNULL methods have been added to CAEDesc_AC to make it easier to think of a CAEDesc_AC as an auto-pointer (or auto-handle, to be more precise). The IsNULL method can be used for testing the dataHandle for NULL.

 

The operator AEDesc& methods have been removed since a CAEDesc_AC IS-A AEDesc.

The original design for CAEDesc had accessor methods for common types, such as GetFSSpec, for example. That was nice for the types that were supported, but there was no reasonable way to extend it to other types. The new CAEValue_AC class is at least as elegant as the old accessor methods, and it makes it easy to support new types using a consistent programming style. The old accessor methods are being kept around for compatibility, and as examples of how to use the new CAEValue_AC classes. They are conditionalized on qOldAEDescAccessors which, for now, defaults to on.

The CompareDesc method has been changed to use the new, extensible CAECompare_AC mechanism.

CTempDesc_AC

CTempDesc was also moved to ACS from MacApp and renamed CTempDesc_AC.

Safe constructors and a safe assignment operator were added to CTempDesc_AC.

CAECompare_AC

The CAECompare_AC class is used for comparing AppleEvent descriptors. It has been designed to be easily extended to support new comparison algorithms and descriptor types.

Override the Compare method to define your own comparisons, and install an instance of your comparer at the beginning of the list so it will take precedence. Comparisons that are not handled by your method should be delegated to the next comparer in the list.

Alternatively, you can remove the default comparer from the list and install your own in its place. In this case, you can call the inherited Compare method for comparisons that your method doesn't handle.

CAEValue_AC

The CAEValue_AC class is a value that has a specific C++ type and also has an Apple Event descriptor type. It is designed to provide a safe and consistent way for getting values in and out of Apple Event descriptors. You can create a CAEDesc_AC from a CAEValue_AC, put a CAEValue_AC into a CAEDesc_AC that is an AEList or AERecord, create a CAEValue_AC from a CAEDesc_AC, and get a CAEValue_AC out of a CAEDesc_AC that is an AERecord.

CAEValue_AC is an abstract class. Derived classes have to define the C++ type of the data for the value, and override the GetPtr, GetMaximumSize and GetSize methods to provide access to the value data. The TemplateAEValue_AC template class can be used for most C++ types.

Because access to a CAEValue_AC's data is through virtual functions, CAEDesc_AC will work with any class that is derived from CAEValue_AC. This allows the same mechanisms to be used for all types, so that new types and user types get the same convenience and safety as types that were originally built into CAEDesc_AC.

The overhead of CAEValue_AC is 8 bytes (the vptr and the fDescriptorType) for each value. The overhead could be reduced by making the GetDescriptorType function virtual and eliminating fDescriptorType, but it seems nice to have fDescriptorType located just before the value data in memory, at least for debugging, and it makes it easier to support values (such as object references) which may have different descriptor types depending on context.
